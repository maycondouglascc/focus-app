## Root Cause & Fix: `--ui-cycle 50 --all-screens` Memory Retention

Initial runs of `focus.exe --ui-cycle 50 --all-screens` exceeded the 30 MB closed-window private memory budget (`start 14.39 -> end 45.57 MB`, `+31.19 MB`) after iterating all six rendered screens across 50 open/close cycles, even though bare `--ui-cycle 50` passed (`12.35 MB`) and off-window `AppShell`/`DemoStore` navigation across 55 iterations stayed flat (`10.71 -> 11.87 MB`).

Isolation via `HeapWalk` and single-cycle `VirtualQuery` diffs established:
1. Live `BUSY` Win32 heap allocations stayed flat across cycles `10..50` (`6.64 -> 6.69 MB`), proving no Rust/COM object leak.
2. Direct2D `DrawText` + WARP device teardown across repeated `Gfx` lifetimes triggered transient allocations on the default Classic NT Heap (`0xFFEEFFEE`), whose segments kept `17–42 MB` of `HEAP_FREE_ENTRY` free-list regions committed across closes until delayed threshold decommit.

Fix implemented in commit `Enable SegmentHeap manifest and flush renderer resources on drop`:
1. Added `win32/focus.manifest` (linked in `win32/build.rs`) opting `focus.exe` into Windows `SegmentHeap` (`<heapType xmlns="http://schemas.microsoft.com/SMI/2020/WindowsSettings">SegmentHeap</heapType>`), which returns freed large/variable blocks cleanly instead of pinning Classic NT Heap segments.
2. Implemented `Drop for Renderer` in `win32/src/ui/render.rs` to detach D2D targets (`SetTarget(None)`), clear cached D2D device resources (`ClearResources(0)`), unlink and commit DirectComposition teardown (`SetContent(None)`, `SetRoot(None)`, `dcomp.Commit()`, `WaitForCommitCompletion()`), and flush the D3D11 immediate context (`ClearState()`, `Flush()`) before dropping the swap chain.

Both `--ui-cycle 50` (`8.56 MB` end, `-1.38 MB` growth) and `--ui-cycle 50 --all-screens` (`10.83 MB` end, `-0.76 MB` growth) now close cleanly well below the `30 MB` private ceiling and `< 1 MB` growth gate without any working-set trimming (`EmptyWorkingSet`).
