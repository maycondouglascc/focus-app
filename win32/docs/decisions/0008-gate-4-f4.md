## Summary of Implemented Architecture (E0–E9)

1. **Always-on Background Architecture (E0–E3)**:
   - Monitor runs on its own low-priority worker thread (`monitor.rs`) using `SetWinEventHook` + `RegisterPowerSettingNotification` (`GUID_CONSOLE_DISPLAY_STATE`) + `WTSRegisterSessionNotification` (`WTSSESSION_NOTIFY`), keeping browser URL capture (`UIAutomationCore`) delay-loaded and conditional on the user's `track_browser_url` / exclusion settings plus a 60s stalled-thread watchdog.
   - Database writes execute on a dedicated `DbThread` (`PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, coalesced 10s flushes, EcoQoS via `SetThreadInformation(ThreadPowerThrottling)` when the window is closed).
   - `focus.exe` uses `#![windows_subsystem = "windows"]` with per-user single-instance mutex coordination (`Local\Focus.Instance.<sid>`) and `FocusTrayWindow` (`Focus.Show` / `Focus.Quit` messages); closing `FocusMainWindow` drops D3D11/D2D1/DWrite/DXGI/AccessKit UIA state while keeping the tray icon alive.

2. **Tray Presence, Startup & Reliability (E4–E8)**:
   - Pure-Rust SDF tray icon rasterizer (`tray/icon.rs`) creates dynamic dark/light/running/paused/error `HICON` handles via `user32!CreateIconFromResourceEx` (no GDI DIB section / ICM color management DLLs needed) and embeds the multi-resolution `.ico` into `focus.exe` via `rc.exe`.
   - Native `TrackPopupMenuEx` menu (Start/Stop, top-5 recent projects submenu, Pause/Resume, Open Focus, Floating Mini Timer, Quit), anchored `PopupWindow` flyout with shared `RichEdit` input + `AwayPrompt`, always-on-top `MiniTimer`, and bidirectional store refresh.
   - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Focus` toggle respecting `StartupApproved\Run` and `RegisterApplicationRestart("--background")` (E6).
   - Delay-loaded `dbghelp.dll` unhandled-exception/vectored minidump handler (`%LOCALAPPDATA%\Focus\crashes`, keep 5 newest, returns `EXCEPTION_EXECUTE_HANDLER` to exit cleanly without blocking on WerFault modal), daily background-I/O `VACUUM INTO` backups (keep 7), weekly `PRAGMA quick_check`, and fatal DB error recovery (`DB_ERROR` tray alert + 5-min probe) (E7).
   - Safe local installer/upgrader (`win32/scripts/install.ps1`) using graceful `--quit`, `.new`/`.prev.exe` swap in `%LOCALAPPDATA%\Programs\Focus`, Start Menu `.lnk`, `HKCU\...\Run\Focus` registration without touching `StartupApproved\Run`, and non-destructive `-Uninstall` (E8).

3. **Startup & Idle DLL Minimization (E9)**:
   - Delay-loaded UI/COM/diagnostic/auxiliary DLLs on `focus.exe` (`d3d11`, `d2d1`, `dcomp`, `dwrite`, `UIAutomationCore`, `dwmapi`, `dbghelp`, `shell32`, `gdi32`, `ole32`, `oleaut32`, `combase`, `comctl32`, `wtsapi32`, `version`, `psapi`), switched tray `HICON` creation to `CreateIconFromResourceEx`, and deferred `RegisterApplicationRestart` until after `Tray::add` + `tray_ms` logging.

### Environment Notes on Startup & `nim_add_failed` in Non-Interactive Desktop

1. Automated commands ran inside a non-interactive virtual desktop with OS/antivirus image inspection active at process creation:
   - A minimal 10-line native Rust binary (`bare_rust_entry_ms`) doing no GUI/tray work already spends `90.89–124.34 ms` from `CreateProcess` to `main()` entry in this environment.
   - Inside `focus.exe`, `entry_ms -> tray_ms` (window creation + `Shell_NotifyIconW`) takes `~16–30 ms`, giving `83.0–115.4 ms` total across 9 of 10 runs (`p50 = 95.40 ms`), with Run 10 hitting an `entry_ms = 193.2 ms` pre-`main` loader spike (`p95 = 237.7 ms`).
   - Because that non-interactive virtual desktop has no `Shell_TrayWnd` (`FindWindowW("Shell_TrayWnd") == 0`), tray log output there shows `[tray] nim_add_failed`; live taskbar icon rendering and `measure-startup.ps1` `p95 < 150 ms` must be confirmed on the user's interactive `Default` desktop.
2. Off-desktop DWM composition throttling makes `--ui-cycle` take `~120.8s` for 50 measured cycles (+ warm-up) in that virtual desktop (`first open 2276.2 ms`), while `diag-drag` still runs at `113.69 fps` and cycle memory growth is `-0.53 MB`.
